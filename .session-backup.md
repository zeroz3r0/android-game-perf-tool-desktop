### Lo que hicimos esta sesión (2026-04-20)

**Objetivo:** auditar que nada esté hardcodeado.

Hallazgos y fixes:

1. ✅ **`AdbBridge.adbPath` migrado a `ToolResolver.find("adb")`** — era el MISMO bug que motivó `ToolResolver` en v4.2.3 para ffmpeg (documentado en `CLAUDE.md`). `which` no funciona en Windows y el único path Windows candidate era `C:\platform-tools\adb.exe`, dejando a todos los usuarios de Android Studio fuera.
2. ✅ **`IosBridge.findFfprobe` migrado a `ToolResolver.find("ffprobe")`** — tercera copia del mismo patrón roto (which-on-Windows + Unix-only list). Windows users con ffprobe via WinGet/Scoop/Chocolatey caían al fallback de validación por tamaño que deja pasar MP4s corruptos.
3. ✅ **`ToolResolver.kt` extendido** con `toolSpecificCandidates` + `adbCandidates` (Android Studio Win/Mac/Linux, Homebrew casks Intel+AS, distros Linux).
4. ✅ **9 tests nuevos** en `ToolResolverTest` — puros, corren en CI Linux.
5. ✅ **`CLAUDE.md`** actualizado con regla operativa: toda herramienta externa DEBE pasar por `ToolResolver.find` desde día 1.
6. ✅ **Release v4.3.1** creada (commit `2fac5c0`).
